# PY Order Check Tool（PY订单核料工具）

一个面向线束/制造场景的 Windows 桌面核料工具。程序读取多个 BOM、即时库存、采购入库、采购订单、采购申请/委外申请等 Excel 数据，根据每个父项订单数量计算子项物料需求、库存欠料、采购在途、未转单申请及最终申请缺口，并输出可追溯的 Excel 核料结果。

> 本仓库建议只发布**脱敏后的源代码与示例数据**。真实 BOM、EAS 导出、库存、价格、采购订单号、供应商/客户信息和公司模板请勿直接上传到公开仓库。

## 功能概览

- 批量读取 ZIP、文件夹或单个 `.xlsx` BOM。
- 自动识别多个父项 BOM，并在桌面界面中输入每个父项的订单数量。
- BOM 很多时支持搜索、滚动和批量录入。
- 按“**单机用量 × 父项订单数量**”计算每个 BOM 的真实材料需求。
- 只有在需求量计算完成后，才按子项物料编码汇总，避免把不同 BOM 的单机用量直接相加。
- 汇总即时库存、采购入库、采购订单剩余入库量、采购申请和委外申请。
- 对“采购申请 → 采购订单 → EAS在途”进行关联去重，避免同一批资源同时计入 `EAS申请` 和 `EAS在途`。
- 生成 `总表`、`订单输入`、`BOM需求明细`、`EAS关联明细` 等工作表。
- 兼容部分非标准 BOM：`物料名称`、`规格型号` 缺失时不会整张 BOM 被跳过。
- 可使用 PyInstaller 打包为 Windows 单文件 EXE，使用者电脑无需安装 Python。

## 业务逻辑与算法公式

### 1. BOM 需求量

设：

- $p$：父项/线束 BOM；
- $m$：子项物料；
- $Q_p$：父项 $p$ 的订单数量；
- $a_{p,m}$：物料 $m$ 在父项 $p$ 中的单机用量；
- $D_m$：物料 $m$ 的总需求量。

每个父项先独立计算：

$$
D_{p,m}=a_{p,m}\times Q_p
$$

然后对相同子项物料编码汇总：

$$
D_m=\sum_{p} a_{p,m}\times Q_p
$$

**重要：不同 BOM 的单机用量不能直接相加。**

例如：

- 父项 `14-2302-0412-00` 订单数量为 500；
- 子项 `14-2301-0055` 单机用量为 380。

则：

$$
D=380\times500=190000
$$

程序最终汇总的是已经乘过订单数量后的 `190000`，而不是先把多个 BOM 中的 `380 + 380` 合并成所谓“单机用量”。

### 2. 库存欠料

设：

- $I_m$：即时库存数量；
- $S_m$：库存欠料数量。

$$
S_m=\max(D_m-I_m,0)
$$

例如需求 190000、库存 5000：

$$
S=\max(190000-5000,0)=185000
$$

### 3. EAS 在途

`EAS在途` 取有效且尚未关闭的采购订单的**剩余入库数量**之和：

$$
T_m=\sum \text{OpenPO\_RemainingQty}_{m}
$$

其中 $T_m$ 为物料 $m$ 的采购在途数量。已作废、取消、驳回、终止或按业务规则已关闭的订单不计入有效在途。

### 4. EAS 申请与采购订单去重

采购申请与采购订单不能重复计入资源。

对一条采购申请 $r$：

- $A_r$：申请有效数量；
- $C_r$：已经转成采购订单的数量；
- $U_r$：尚未转采购订单的申请剩余量。

$$
U_r=\max(A_r-C_r,0)
$$

总表中的 `EAS申请` 只统计尚未转单的申请，以及有效的委外申请：

$$
A_m^{EAS}=\sum_{r\in m}U_r+\sum_{w\in m}W_w
$$

其中 $W_w$ 为有效委外申请数量。

#### 申请与采购订单的关联优先级

1. **精确关联**：如果采购订单导出包含 `源单编号`、`采购申请单号`、`来源申请单号` 等字段，则按申请单号精确匹配。
2. **兼容推定**：若导出没有可用的源单字段，可按“同物料编码 + 申请日期不晚于采购日期 + FIFO”进行匹配。
3. 已经分配到采购订单的申请数量会从 `EAS申请` 中扣除，因此不会同时出现在 `EAS申请` 和 `EAS在途`。

> FIFO 属于缺少源单字段时的兼容推定。正式生产环境更推荐 EAS 导出中保留真实的源申请单号/源单分录，以获得可审计的精确关联。

### 5. 采购缺口

设 $P_m$ 为采购缺口：

$$
P_m=\max(S_m-T_m,0)
$$

即先用采购在途覆盖库存欠料。

### 6. 申请缺口

设 $G_m$ 为最终申请缺口：

$$
G_m=\max(P_m-A_m^{EAS},0)
$$

含义：采购在途和“尚未转采购订单的有效申请”都考虑后，仍然需要新增申请的数量。

### 7. 库存结余

$$
B_m=I_m-D_m
$$

$B_m>0$ 表示当前库存覆盖需求后仍有结余；$B_m<0$ 表示仅从库存角度存在缺口。

### 8. 套数折算

当某个子项在本次有效父项中具有唯一、明确的单机用量 $a_m$ 时：

$$
\text{库存结余套数}=\frac{B_m}{a_m}
$$

$$
\text{在途套数}=\frac{T_m}{a_m}
$$

$$
\text{合计结余套数}=\frac{B_m+T_m}{a_m}
$$

如果同一物料同时用于多个父项，而且各父项单机用量不同，则“套数”没有唯一换算基准，程序不会强行用一个错误的单机用量换算。

## BOM 兼容规则

BOM 最低必须包含以下字段：

| 必需字段 | 用途 |
| --- | --- |
| 父项物料编码 | 识别父项/线束 |
| 物料编码 | 识别子项物料 |
| 额定消耗 | 单机用量 |
| 计量单位 | 数量单位 |

以下字段为可选：

- `物料名称`
- `规格型号`

如果名称缺失，程序会尝试从其它 BOM 中相同物料编码回填；父项名称缺失时也可尝试从文件名识别。因此不会因为缺少“物料名称”整张 BOM 被跳过。

## 输出结果

程序生成的 Excel 包含：

| 工作表 | 内容 |
| --- | --- |
| 总表 | 物料需求、库存、欠料、在途、申请、缺口、金额等最终核料结果 |
| 订单输入 | 每个父项 BOM 与本次订单数量 |
| BOM需求明细 | 父项、子项、单机用量、订单数量、需求量及计算过程 |
| EAS关联明细 | 采购申请、采购订单、转单数量、未转申请、剩余在途及关联方式 |

## 运行环境

源码运行推荐：

- Windows 10 / 11
- Python 3.8+
- `openpyxl 3.1.5`
- Tkinter（标准 Python Windows 安装通常自带）

安装依赖：

```bash
pip install -r requirements.txt
```

运行：

```bash
python app.pyw
```

## 打包为单文件 EXE

开发环境额外安装：

```bash
pip install -r requirements-dev.txt
```

本项目提供 `build_onefile.bat`。打包前将本地/脱敏后的核料模板命名为：

```text
template.xlsx
```

放在项目根目录，然后双击：

```text
build_onefile.bat
```

成功后得到：

```text
dist/PY_Order_Check_Tool.exe
```

`--onefile` 版本可以只分发一个 EXE，目标电脑无需安装 Python。

## 数据处理流程

```text
多个 BOM
   ↓
识别父项与子项
   ↓
输入各父项订单数量
   ↓
单机用量 × 对应订单数量
   ↓
按子项物料编码汇总总需求
   ↓
读取即时库存
   ↓
计算库存欠料
   ↓
读取采购订单剩余入库量 → EAS在途
   ↓
采购申请 ↔ 采购订单关联去重
   ↓
得到未转单 EAS申请
   ↓
计算采购缺口 / 申请缺口
   ↓
输出总表 + 明细 + 关联审计表
```

## 当前限制

- 当采购订单缺少真实源申请单号时，FIFO 关联属于推定关系，精确性取决于导出字段与业务流程。
- Excel 列名发生较大变化时，需要维护字段别名/识别规则。
- 本工具用于业务核料辅助，正式采购/生产决策仍应以 ERP/EAS 原始单据与审批流程为准。
